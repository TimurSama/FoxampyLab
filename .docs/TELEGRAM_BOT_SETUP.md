## 🤖 Настройка Telegram бота

### Шаг 1: Создание бота через BotFather

1. Откройте Telegram и найдите бота [@BotFather](https://t.me/BotFather)
2. Отправьте команду `/newbot`
3. Следуйте инструкциям:
   - Введите имя бота (например: `Foxampy Lab Orders Bot`)
   - Введите username бота (например: `FoxampyLab_contact_bot`)
4. **Сохраните токен бота**, который выдаст BotFather:
   ```
   8224553051:AAGhMoyvUojdI5Mzli2D7LWlkMr_Xah4Deg
   ```

### Шаг 2: Получение вашего Telegram ID

Ваш ID администратора: `268494758`

**Как узнать свой ID (если нужно):**
1. Найдите бота [@userinfobot](https://t.me/userinfobot)
2. Отправьте ему `/start`
3. Бот покажет ваш ID

### Шаг 3: Начало чата с ботом (ВАЖНО!)

⚠️ **КРИТИЧЕСКИЙ ШАГ**: Чтобы бот мог отправлять вам сообщения, вы ДОЛЖНЫ начать с ним чат!

1. Найдите вашего бота в Telegram по username (например: `@FoxampyLab_contact_bot`)
2. Нажмите "Start" или отправьте команду `/start`
3. Бот должен ответить (даже если у него нет команд)

**Почему это важно:**
- Telegram не позволяет ботам отправлять сообщения пользователям, которые не начали с ними чат
- После начала чата бот получает возможность отправлять вам уведомления

### Шаг 4: Настройка команд бота (опционально)

Через BotFather можно настроить команды:
1. Откройте [@BotFather](https://t.me/BotFather)
2. Отправьте `/setcommands`
3. Выберите вашего бота
4. Добавьте команды:
   ```
   start - Начать работу с ботом
   help - Помощь
   status - Статус заявок
   ```

## 💻 Локальная настройка

### Шаг 1: Создание файла `.env.local`

В корне проекта создайте файл `.env.local` (если его нет):

```bash
# Telegram Bot Configuration
NEXT_PUBLIC_TELEGRAM_BOT_TOKEN=8224553051:AAGhMoyvUojdI5Mzli2D7LWlkMr_Xah4Deg
NEXT_PUBLIC_TELEGRAM_ADMIN_ID=268494758

# Site URL (для production)
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

⚠️ **ВАЖНО**: 
- Файл `.env.local` уже добавлен в `.gitignore` и НЕ будет закоммичен в Git
- Никогда не публикуйте токен бота в открытом доступе!

### Шаг 2: Перезапуск dev-сервера

После создания/изменения `.env.local`:

```bash
# Остановите текущий сервер (Ctrl+C)
# Затем запустите заново:
npm run dev
```

### Шаг 3: Проверка локальной работы

1. Откройте сайт: `http://localhost:3000`
2. Заполните любую форму (консультация, услуги, контакты)
3. Отправьте заявку
4. Проверьте Telegram - должно прийти уведомление

## 🚀 Настройка GitHub Secrets для автодеплоя

### Шаг 1: Добавление секретов в GitHub

1. Откройте ваш репозиторий на GitHub: `https://github.com/TimurSama/FoxampyLab`
2. Перейдите в **Settings** → **Secrets and variables** → **Actions**
3. Нажмите **New repository secret** для каждого секрета:

#### Секрет 1: `NEXT_PUBLIC_TELEGRAM_BOT_TOKEN`
- **Name**: `NEXT_PUBLIC_TELEGRAM_BOT_TOKEN`
- **Value**: `8224553051:AAGhMoyvUojdI5Mzli2D7LWlkMr_Xah4Deg`
- Нажмите **Add secret**

#### Секрет 2: `NEXT_PUBLIC_TELEGRAM_ADMIN_ID`
- **Name**: `NEXT_PUBLIC_TELEGRAM_ADMIN_ID`
- **Value**: `268494758`
- Нажмите **Add secret**

#### Секрет 3: `NEXT_PUBLIC_SITE_URL` (если используется)
- **Name**: `NEXT_PUBLIC_SITE_URL`
- **Value**: `https://timursama.github.io/FoxampyLab` (или ваш production URL)
- Нажмите **Add secret**

### Шаг 2: Проверка GitHub Actions workflow

Убедитесь, что в файле `.github/workflows/deploy.yml` (или аналогичном) есть секция с переменными окружения:

```yaml
env:
  NEXT_PUBLIC_TELEGRAM_BOT_TOKEN: ${{ secrets.NEXT_PUBLIC_TELEGRAM_BOT_TOKEN }}
  NEXT_PUBLIC_TELEGRAM_ADMIN_ID: ${{ secrets.NEXT_PUBLIC_TELEGRAM_ADMIN_ID }}
  NEXT_PUBLIC_SITE_URL: ${{ secrets.NEXT_PUBLIC_SITE_URL }}
```

### Шаг 3: Проверка автодеплоя

1. Сделайте commit и push изменений
2. Откройте вкладку **Actions** в GitHub
3. Дождитесь завершения деплоя
4. Проверьте, что сайт работает и бот отправляет уведомления

## 🔒 Безопасность

### Защита токена бота

✅ **ПРАВИЛЬНО:**
- Токен хранится в `.env.local` (локально)
- Токен хранится в GitHub Secrets (для production)
- Файл `.env.local` в `.gitignore`
- Использование переменных окружения `NEXT_PUBLIC_*`

❌ **НИКОГДА НЕ ДЕЛАЙТЕ:**
- Не коммитьте `.env.local` в Git
- Не публикуйте токен в коде
- Не делитесь токеном в открытых чатах/форумах
- Не используйте токен в клиентском коде напрямую

### Ограничения токена

Токен бота имеет следующие возможности:
- ✅ Отправка сообщений администратору
- ✅ Чтение сообщений от администратора
- ❌ НЕ может читать сообщения других пользователей
- ❌ НЕ может отправлять сообщения пользователям без их разрешения

### Что делать, если токен скомпрометирован

1. Немедленно отзовите токен через [@BotFather](https://t.me/BotFather):
   - `/revoke` → выберите бота → подтвердите
2. Создайте новый токен через `/newbot` или `/token`
3. Обновите секреты в GitHub
4. Обновите `.env.local` локально

## 🔧 Troubleshooting

### Проблема: Сообщения не приходят

**Решение:**
1. ✅ Проверьте, что начали чат с ботом (`/start`)
2. ✅ Проверьте правильность токена в `.env.local`
3. ✅ Проверьте правильность `TELEGRAM_ADMIN_ID`
4. ✅ Перезапустите dev-сервер после изменения `.env.local`
5. ✅ Проверьте консоль браузера на ошибки
6. ✅ Проверьте, что бот не заблокирован

### Проблема: Ошибка "Telegram bot credentials not configured"

**Решение:**
1. Проверьте наличие файла `.env.local`
2. Проверьте правильность названий переменных:
   - `NEXT_PUBLIC_TELEGRAM_BOT_TOKEN`
   - `NEXT_PUBLIC_TELEGRAM_ADMIN_ID`
3. Перезапустите dev-сервер
4. Убедитесь, что переменные не пустые

### Проблема: Ошибка "Telegram API Error: Bad Request"

**Решение:**
1. Проверьте правильность токена бота
2. Проверьте, что бот активен (напишите ему `/start`)
3. Проверьте правильность `TELEGRAM_ADMIN_ID`
4. Убедитесь, что начали чат с ботом

### Проблема: Бот работает локально, но не работает на GitHub Pages

**Решение:**
1. Проверьте, что секреты добавлены в GitHub Secrets
2. Проверьте GitHub Actions workflow - должны быть переменные окружения
3. Проверьте логи GitHub Actions на ошибки
4. Убедитесь, что переменные окружения правильно передаются в build процесс

### Проблема: Fallback открывает Telegram, но не отправляет сообщение

**Решение:**
Это нормальное поведение, если бот не настроен. Fallback открывает Telegram бота с предзаполненным сообщением, которое пользователь должен отправить вручную.
